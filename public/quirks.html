Known Quirks

On iPhone, Safari 26 and later tints the strip behind the address bar with the background-color of <body>. It follows the color when the page changes it.

One quirk breaks this. A fixed element touches the bottom edge and has no background color. A child of the element has one, such as a button, and the center of the element is empty. The page then changes the <body> color with JavaScript, for example in a theme switch. The strip keeps the first color.

Try It

  1. Select transparent for the fixed element at the bottom. The page reloads.
  2. Switch to dark.
  3. Look at the strip at the bottom of the screen on an iPhone.

What Happens

  • transparent: the element holds the small Fixed chip and an empty area. The strip keeps the first body color. The top of the screen and the page change.
  • its own background-color: the strip follows the body, because the element changes color with the body.
  • The same transparent element at bottom: 100px does not cause the quirk.
  • A transparent element with no child that has a background color does not cause the quirk.

What Fixes It

  • Remove the fixed element and append it again after about 500 ms:
  • Give the fixed element a real background-color.
  • The user opens the tab overview and returns to the tab.

What Does Not Help

  • Replacing the fixed element with a clone:
  • Toggling display.
  • Adding a backdrop-filter to the element or to the empty area.
  • Nudging bottom by 1px.
  • Leaving Safari and returning.

Tested

Safari on iOS 26 and iOS 27. Notes and code examples: Known Quirks.
